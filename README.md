# Synthetic-Healthcare-Data-Factory
A synthetic data generation workflow that creates fictional healthcare Prior Authorization records using large language models. It uses GPT, Llama, and Gemini to explore different prompting strategies, generate structured patient records, compare model outputs, and validate datasets before exporting them in CSV and JSON formats.

## Objective
To generate realistic fictional healthcare records for testing and data analysis without using actual patient information. The project focuses on improving data diversity, handling incomplete records, comparing language models, and preparing reusable structured datasets.

## Steps Followed

1. **Define the Healthcare Dataset**
   - Selected Prior Authorization as the healthcare use case.
   - Defined fields such as patient ID, age, gender, insurance provider, requested service, diagnosis category, physician orders, clinical notes, previous imaging, and authorization status.

2. **Environment and Model Setup**
   - Imported Python libraries, including Pandas, JSON, OpenAI, and dotenv.
   - Configured API credentials and initialized GPT-4.1-mini for generating synthetic records.

3. **Generate Initial Synthetic Records**
   - Created a standard prompt requesting five fictional Prior Authorization records.
   - Instructed the model to return structured JSON data.
   - Generated records containing different medical services, diagnoses, and authorization statuses.

4. **Convert Responses into Structured Data**
   - Removed unnecessary Markdown formatting from the generated responses.
   - Parsed the JSON text into Python objects.
   - Converted the records into a Pandas DataFrame for easier inspection and analysis.

5. **Improve Data Diversity**
   - Created a diversity-focused prompt to generate records across different ages, genders, insurance providers, medical services, and diagnoses.
   - Generated another set of five records.
   - Compared unique services, diagnosis categories, and authorization statuses with the initial dataset.

6. **Generate Edge-Case Records**
   - Developed a separate prompt for unusual or incomplete Prior Authorization requests.
   - Generated records involving missing physician orders, clinical notes, or previous imaging.
   - Examined the resulting authorization statuses and incomplete information.

7. **Generate Data Using Multiple Models**
   - Used GPT-4.1-mini through the OpenAI API.
   - Configured Llama through a local Ollama endpoint.
   - Added Gemini using Google's GenAI SDK.
   - Converted the generated responses into Pandas DataFrames for comparison.

8. **Create a Reusable Generation Function**
   - Developed a Python function that accepts a model client, model name, and prompt.
   - Combined model requests, JSON extraction, and DataFrame creation into one reusable workflow.
   - Used the function to reduce repeated code when generating records.

9. **Compare Model Outputs**
   - Compared the number of records generated by GPT, Llama, and Gemini.
   - Examined unique medical services, diagnosis categories, and authorization statuses.
   - Explored how different models responded to the same healthcare data generation task.

10. **Build a Combined Synthetic Dataset**
    - Generated separate batches using standard, diversity-focused, and edge-case prompts.
    - Added `prompt_type` and `model` columns to identify how each record was generated.
    - Combined the batches into a single Pandas DataFrame.

11. **Perform Data Quality Checks**
    - Checked the dataset for missing values and duplicate records.
    - Examined duplicate patient IDs and invalid age values.
    - Validated authorization statuses against Approved, Pending, and Denied.
    - Analyzed record distributions across different prompting strategies.

12. **Export the Dataset**
    - Exported the combined dataset to CSV format for analysis.
    - Saved the same dataset in JSON format for reuse in other applications.

## Outcome
Developed a reusable synthetic healthcare data generation workflow that combines structured prompting, multiple language models, and data quality checks.

The final exported dataset contains 15 fictional Prior Authorization records:
- 5 standard records
- 5 diversity-focused records
- 5 edge-case records

The project demonstrates prompt engineering, structured JSON generation, multi-model comparison, Pandas-based data processing, and dataset validation.
